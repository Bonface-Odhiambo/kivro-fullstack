# 🔍 OTP Redirect Debug - After Verification

## ISSUE: OTP Modal Shows, But No Redirect After Verification

### WHAT TO TEST NOW:

1. **Sign in with email/password**
2. **Enter OTP code** (any 6-digit code should work in dev mode)
3. **Watch console logs** for these specific messages:

### EXPECTED CONSOLE LOGS:

```
✅ OTP verified successfully
✅ User is already authenticated, proceeding with redirect...
✅ OTP verification complete. Flags reset: { otpRequired: false, otpRequiredRef: false, otpFlowActiveRef: false }
🔍 Checking current session for manual redirect...
✅ Session found, manually triggering redirect...
🎯 Redirecting to: /dashboard
✅ OTP verification complete. Redirect should now proceed.
```

### POSSIBLE ISSUES TO LOOK FOR:

**1. OTP Verification Failing:**
```
❌ Verification Failed
Invalid OTP code. Please try again.
```
- **Solution**: Try any 6-digit code (e.g., 123456) - should work in dev mode

**2. No Session After Verification:**
```
❌ No session found after OTP verification
```
- **Solution**: User might have been signed out during OTP flow

**3. Backend OTP Error:**
```
❌ OTP verification error: [error details]
```
- **Solution**: Check if backend is running and OTP migration is applied

**4. getDashboardRoute Error:**
```
Error determining dashboard route: [error details]
```
- **Solution**: Profile creation issue

### DEBUGGING STEPS:

**If OTP verification fails:**
1. Check backend logs for OTP verification
2. Ensure backend is running on port 3001
3. Try different 6-digit codes

**If no session found:**
1. Check if user is still authenticated: `supabase.auth.getUser()`
2. Look for sign-out calls in console

**If redirect doesn't happen:**
1. Check for navigation errors
2. Verify dashboard route exists
3. Check for React Router issues

### MANUAL TEST:

After entering OTP, you can also manually check session:
```javascript
// In browser console:
const { data: { session } } = await supabase.auth.getSession();
console.log('Current session:', session);
```

### FALLBACK SOLUTION:

If automatic redirect fails, you can manually navigate:
```javascript
// In browser console:
window.location.href = '/dashboard';
```

The enhanced logging will show exactly where the redirect flow is breaking!
