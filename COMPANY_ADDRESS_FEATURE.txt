## HOW IT WORKS
================================================================================

### FOR USERS:
-------------
1. Users can generate a FREE personal address (1 free address)
2. With an active subscription, users can generate a company address
3. Company addresses require:
   - Company name (required)
   - Phone number (required)
   - Company registration number (optional)
   - Company email (optional)
   - Company phone (optional)

### ADDRESS TYPES:
-----------------
Personal Address:
  - Format: KV-ABC123-4567, Mogadishu
  - Free tier: 1 address
  - Use: Personal mail, deliveries

Company Address:
  - Format: Company Name, KV-BIZ-ABC123-4567, Mogadishu
  - Requires: Active subscription
  - Limit: 1 per user (can be increased)
  - Use: Business mail, invoices, official documents

### FILTERING:
-------------
Users can filter addresses by:
  - All Addresses (shows everything)
  - Personal (shows only personal addresses)
  - Company (shows only company addresses)

Search works across:
  - KIVRO codes
  - Display addresses
  - Regions/cities
  - Company names

## API USAGE EXAMPLES
================================================================================

### Generate Company Address
----------------------------
POST /api/addresses/generate-company
Headers:
  Authorization: Bearer <JWT_TOKEN>
  Content-Type: application/json

Body:
{
  "phone_number": "+252612345678",
  "company_name": "Kivro Business Solutions",
  "company_registration_number": "REG-2025-12345",
  "company_email": "info@kivrobusiness.com",
  "company_phone": "+252-1-234567",
  "region": "mogadishu",
  "landmark": "Near Central Market"
}

Response (Success):
{
  "success": true,
  "message": "Company address generated successfully",
  "address": {
    "id": "uuid",
    "address_type": "company",
    "kivro_code": "KV-BIZ-ABC123-4567",
    "display_address": "Kivro Business Solutions, KV-BIZ-ABC123-4567, Mogadishu",
    "company_name": "Kivro Business Solutions",
    "company_registration_number": "REG-2025-12345",
    "company_email": "info@kivrobusiness.com",
    "company_phone": "+252-1-234567",
    ...
  }
}

Response (No Subscription):
{
  "error": "Subscription required",
  "message": "Company addresses require an active subscription. Please upgrade your account.",
  "upgrade_required": true
}

Response (Limit Reached):
{
  "error": "Company address limit reached",
  "message": "You already have a company address. Please contact support to add more.",
  "limit_reached": true
}

### List Addresses (Filtered)
-----------------------------
GET /api/addresses?address_type=company
Headers:
  Authorization: Bearer <JWT_TOKEN>

Response:
{
  "success": true,
  "addresses": [
    {
      "id": "uuid",
      "address_type": "company",
      "company_name": "Kivro Business Solutions",
      ...
    }
  ]
}

## BUSINESS RULES
================================================================================

1. **Free Tier**: 1 personal address only
2. **Subscription Required**: For company addresses
3. **Company Address Limit**: 1 per user (can be increased by admin)
4. **Address Prefix**: Company addresses get "BIZ" in KIVRO code
5. **Company Info**: Name is required, other fields optional
6. **Deactivation**: Both personal and company addresses can be deactivated
7. **Search**: Company names are searchable
8. **Filtering**: Users can filter by address type

## TECHNICAL NOTES
================================================================================

### Database Schema:
-------------------
- address_type: VARCHAR(20) with CHECK constraint
- Default value: 'personal' for backward compatibility
- Indexed for fast filtering
- Company fields are nullable (optional)

### Backend Validation:
----------------------
- Phone number format validation
- Company name length: 2-200 characters
- Email format validation (if provided)
- Subscription status check
- Address limit enforcement

### Frontend State:
------------------
- addressTypeFilter: 'all' | 'personal' | 'company'
- companyInfo: Object with company details
- showCompanyForm: Boolean toggle
- Separate counters for each address type

### API Security:
----------------
- JWT authentication required
- User can only access their own addresses
- RLS policies apply to all address types
- Subscription verification for company addresses
