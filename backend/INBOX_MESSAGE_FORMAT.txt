INBOX MESSAGE FORMAT - Backend Reference
==========================================

To ensure messages display correctly in the inbox with amounts and due dates,
the backend should populate the `metadata` field with the following structure:

COMPLETE METADATA STRUCTURE:
{
  // Payment Information
  "fine_amount": 2560.00,           // Number - Amount to be charged (required for displaying amount)
  "due_date": "2025-11-30",         // String (ISO date) - Payment due date (required for due date badge)
  "currency": "SEK",                // String - Currency code (optional, defaults to SEK)
  "late_fee": 500.00,               // Number - Late payment fee (optional)
  "payment_reference": "REF123",    // String - Payment reference number (optional)
  
  // Invoice/Bill Details
  "invoice_label": "SKATTEVERKET",  // String - Label for invoice header (e.g., "SKATTEVERKET", "INV0001")
  "business_number": "21212121212", // String - Sender's business/tax number
  
  // Sender Address Information
  "sender_address": "Kidstar 58 A2, Gulberg 3 Block A2, Ghalib Market, Lahore, Pakistan",
  "sender_city": "Gulberg",         // String - Sender's city
  "sender_postal": "54660",         // String - Sender's postal code
  "sender_phone": "03227874375",    // String - Sender's phone number
  "sender_email": "Skatteverket@gmail.com", // String - Sender's email
  
  // Recipient/Bill To Information
  "recipient_info": {
    "name": "Skatteverket",         // String - Recipient name
    "address": "924 C, Canal View Housing Society, Lahore Gulberg",
    "city": "Gulberg",              // String - Recipient city
    "postal": "54500",              // String - Recipient postal code
    "phone": "03227874375",         // String - Recipient phone
    "tax_id": "12121212121",        // String - Recipient tax/business ID
    "email": "Skatteverket@gmail.com" // String - Recipient email
  },
  
  // Payment Details (Right Sidebar)
  "payment_status": "Unhandled",    // String - Payment status (e.g., "Unhandled", "Paid", "Pending")
  "ocr_number": "5656879798567",    // String - OCR reference number for payment
  "bankgiro": "2356898",            // String - Bankgiro account number
  
  // Contact Details (Optional - if no payment info)
  "contact_info": "Lorem ipsum is a dummy or placeholder text commonly used in graphic design, publishing, and web development.",
  "contact_description": "For questions about this message...", // Alternative to contact_info
  "contact_phone": "03227874375",   // String - Contact phone number
  "contact_email": "support@example.com", // String - Contact email
  "contact_website": "https://abcd.xyz", // String - Contact website URL
  "contact_link": "https://abcd.xyz"     // String - Alternative contact link (if no website)
}

EXAMPLE MESSAGE WITH PAYMENT:
{
  "user_id": "user-uuid",
  "subject": "Traffic Violation Fine",
  "message_body": "You have been issued a traffic violation fine...",
  "message_type": "fine",
  "priority": "high",
  "sender_type": "government",
  "sender_id": "sender-uuid",
  "metadata": {
    "fine_amount": 2560.00,
    "due_date": "2025-11-30",
    "currency": "SEK",
    "violation_code": "SPEED-001"
  }
}

FRONTEND DISPLAY:
- If `metadata.fine_amount` exists: Shows "SEK 2,560.00" on the right
- If `metadata.due_date` exists: Shows orange badge "Due on 11/30/25"
- Date is always shown below amount in format "13 Nov"

MESSAGE TYPES THAT SHOULD INCLUDE AMOUNTS:
- fine (traffic violations, penalties)
- invoice (bills, charges)
- payment_request (any payment required)

MESSAGE TYPES THAT MAY NOT NEED AMOUNTS:
- notification (general info)
- alert (warnings, reminders)
- announcement (news, updates)

BACKEND API ENDPOINT:
POST /api/inbox/send
- Ensure metadata field is properly validated and stored as JSONB
- Validate fine_amount is a positive number
- Validate due_date is a valid ISO date string
- Return proper error messages if validation fails
