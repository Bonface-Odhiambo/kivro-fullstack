1. OVERVIEW
================================================================================

The KIVRO Government Agency API allows authorized government organizations to
send official communications directly to citizens' digital inboxes. This system
is similar to Sweden's "Mina Meddelanden" digital mailbox system.

Base URL (Production): https://kivro-fullstack.vercel.app
Base URL (Development): http://localhost:3001

All API requests require authentication via API Key.


================================================================================
2. AUTHENTICATION
================================================================================

All API requests must include your organization's API key in the request header.

Header Name: X-API-Key
Header Value: Your unique API key (provided by KIVRO)

Example:
  X-API-Key: police_api_key_76dddb62d58a7bbcf410a5bb1e3319cf

Security Notes:
- Keep your API key confidential
- Do not share your API key in public repositories
- Rotate your API key periodically
- Use environment variables to store API keys

3. API ENDPOINTS
================================================================================

3.1 SEND MESSAGE TO SINGLE USER
--------------------------------
Endpoint: POST /api/inbox/send
Purpose: Send an official message to a specific KIVRO user

Required Headers:
  Content-Type: application/json
  X-API-Key: YOUR_API_KEY

Request Body Parameters:
  - user_id (required, UUID): The KIVRO user's unique identifier
  - category (required, string): Message category (see section 3.3)
  - subject (required, string): Message subject line
  - message_body (required, string): Full message content
  - message_type (optional, string): Type of message
      Options: notification, fine, invoice, certificate, alert, reminder
      Default: notification
  - priority (optional, string): Message priority level
      Options: low, normal, high, urgent
      Default: normal
  - reference_number (optional, string): Your internal reference number
  - metadata (optional, object): Additional structured data (see section 3.4)


3.2 SEND MESSAGE TO MULTIPLE USERS (BULK)
------------------------------------------
Endpoint: POST /api/inbox/send-bulk
Purpose: Send the same message to multiple KIVRO users at once

Required Headers:
  Content-Type: application/json
  X-API-Key: YOUR_API_KEY

Request Body Parameters:
  - user_ids (required, array): Array of KIVRO user UUIDs
  - category (required, string): Message category
  - subject (required, string): Message subject line
  - message_body (required, string): Full message content
  - message_type (optional, string): Type of message
  - priority (optional, string): Message priority level
  - reference_number_prefix (optional, string): Prefix for auto-generated refs
      Example: "NOTICE-2025" will generate NOTICE-2025-0001, NOTICE-2025-0002, etc.
  - metadata (optional, object): Additional structured data


3.3 AVAILABLE MESSAGE CATEGORIES
---------------------------------
Use these exact category names in your requests:

  - Traffic Violations
  - Tax & Revenue
  - Health Services
  - Legal & Court
  - Education
  - Utilities
  - Immigration
  - Municipal Services
  - Employment
  - General Notices


3.4 METADATA STRUCTURE
-----------------------
The metadata field allows you to include structured data specific to your
message type. Common metadata fields:

For Fines/Invoices:
  {
    "fine_amount": 100,
    "currency": "USD",
    "due_date": "2025-03-15",
    "violation_type": "speeding",
    "can_appeal": true,
    "appeal_deadline": "2025-02-15"
  }

For Appointments:
  {
    "appointment_date": "2025-02-20",
    "appointment_time": "10:00 AM",
    "location": "Main Office, Room 201",
    "confirmation_required": true
  }

For Certificates:
  {
    "certificate_type": "birth_certificate",
    "issue_date": "2025-01-15",
    "expiry_date": "2030-01-15",
    "certificate_number": "BC-2025-12345"
  }

4. REQUEST EXAMPLES

4.1 EXAMPLE 1: TRAFFIC VIOLATION NOTICE
----------------------------------------

PowerShell:
-----------
$headers = @{
    "Content-Type" = "application/json"
    "X-API-Key" = "police_api_key_76dddb62d58a7bbcf410a5bb1e3319cf"
}

$body = @{
    user_id = "8a34a6c4-b41b-47b9-852a-4a666f4c6dc4"
    category = "Traffic Violations"
    subject = "Traffic Violation Notice - Speeding"
    message_body = "Dear Citizen,

This is an official notice regarding a traffic violation detected on your vehicle.

Violation Details:
- Date: January 10, 2025
- Time: 14:35
- Location: Maka Al Mukarama Road, Mogadishu
- Violation: Exceeding speed limit (85 km/h in 50 km/h zone)

Fine Amount: $50 USD
Payment Due: February 10, 2025

You have the right to appeal this fine within 14 days.

Somalia Police Force"
    message_type = "fine"
    priority = "high"
    reference_number = "SPF-2025-001234"
    metadata = @{
        fine_amount = 50
        currency = "USD"
        due_date = "2025-02-10"
        violation_type = "speeding"
        speed_recorded = 85
        speed_limit = 50
        location = "Maka Al Mukarama Road, Mogadishu"
        can_appeal = $true
        appeal_deadline = "2025-01-24"
    }
} | ConvertTo-Json -Depth 10

Invoke-RestMethod -Uri "https://kivro-fullstack.vercel.app/api/inbox/send" -Method Post -Headers $headers -Body $body

5.3 ERROR RESPONSES
-------------------

Authentication Error:
HTTP Status: 401 Unauthorized
{
  "success": false,
  "error": "Invalid or inactive API key"
}

User Not Found:
HTTP Status: 404 Not Found
{
  "success": false,
  "error": "User not found"
}

Invalid Category:
HTTP Status: 400 Bad Request
{
  "success": false,
  "error": "Category 'Invalid Category' not found. Available categories: Traffic Violations, Tax & Revenue, Health Services, Legal & Court, Education, Utilities, Immigration, Municipal Services, Employment, General Notices"
}

Validation Error:
HTTP Status: 400 Bad Request
{
  "success": false,
  "errors": [
    {
      "field": "user_id",
      "message": "Valid user_id is required"
    },
    {
      "field": "subject",
      "message": "Subject is required"
    }
  ]
}

Server Error:
HTTP Status: 500 Internal Server Error
{
  "success": false,
  "error": "Internal server error"
}


================================================================================
6. ERROR HANDLING
================================================================================

6.1 RETRY LOGIC
---------------
Implement exponential backoff for failed requests:
- First retry: Wait 1 second
- Second retry: Wait 2 seconds
- Third retry: Wait 4 seconds
- Maximum retries: 3

6.2 TIMEOUT SETTINGS
--------------------
- Connection timeout: 10 seconds
- Read timeout: 30 seconds

6.3 ERROR LOGGING
-----------------
Log all API errors with:
- Timestamp
- Request ID (if provided)
- Error message
- Request payload (excluding sensitive data)
- Response status code

7. BEST PRACTICES
================================================================================

7.1 MESSAGE CONTENT
-------------------
✓ Use clear, professional language
✓ Include all relevant details (dates, amounts, locations)
✓ Provide contact information for inquiries
✓ Specify deadlines and consequences clearly
✓ Use proper formatting (line breaks, bullet points)
✗ Avoid using ALL CAPS (except for urgent alerts)
✗ Don't include sensitive personal data unnecessarily
✗ Avoid technical jargon

7.2 PRIORITY LEVELS
-------------------
- LOW: General information, non-urgent reminders
- NORMAL: Standard communications, routine notices
- HIGH: Important deadlines, payment reminders, violations
- URGENT: Emergency alerts, critical deadlines, safety issues

7.3 METADATA USAGE
------------------
✓ Include structured data for automated processing
✓ Use consistent field names across similar messages
✓ Include payment/appeal deadlines when applicable
✓ Add location data for appointments or violations

7.4 BULK SENDING
----------------
✓ Batch messages in groups of 100 or fewer
✓ Add delays between batches (1-2 seconds)
✓ Use reference_number_prefix for tracking
✓ Monitor success rates and retry failures

7.5 SECURITY
------------
✓ Store API keys in environment variables
✓ Use HTTPS for all API requests
✓ Rotate API keys every 90 days
✓ Implement IP whitelisting if possible
✓ Log all API usage for audit trails
✗ Never commit API keys to version control
✗ Don't share API keys via email or chat

8.3 SAMPLE TEST SCRIPT (PowerShell)
------------------------------------
# Test 1: Valid Request
Write-Host "Test 1: Sending valid message..." -ForegroundColor Yellow

$headers = @{
    "Content-Type" = "application/json"
    "X-API-Key" = "YOUR_API_KEY_HERE"
}

$body = @{
    user_id = "8a34a6c4-b41b-47b9-852a-4a666f4c6dc4"
    category = "General Notices"
    subject = "API Test Message"
    message_body = "This is a test message from the API integration."
    message_type = "notification"
    priority = "low"
} | ConvertTo-Json -Depth 10

try {
    $response = Invoke-RestMethod -Uri "http://localhost:3001/api/inbox/send" -Method Post -Headers $headers -Body $body
    Write-Host "✓ Test 1 PASSED" -ForegroundColor Green
    Write-Host "Message ID: $($response.data.id)" -ForegroundColor Cyan
} catch {
    Write-Host "✗ Test 1 FAILED" -ForegroundColor Red
    Write-Host $_.Exception.Message -ForegroundColor Red
}

# Test 2: Invalid API Key
Write-Host "`nTest 2: Testing invalid API key..." -ForegroundColor Yellow

$headers["X-API-Key"] = "invalid_key_12345"

try {
    $response = Invoke-RestMethod -Uri "http://localhost:3001/api/inbox/send" -Method Post -Headers $headers -Body $body
    Write-Host "✗ Test 2 FAILED (Should have been rejected)" -ForegroundColor Red
} catch {
    if ($_.Exception.Response.StatusCode -eq 401) {
        Write-Host "✓ Test 2 PASSED (Correctly rejected invalid key)" -ForegroundColor Green
    } else {
        Write-Host "✗ Test 2 FAILED (Unexpected error)" -ForegroundColor Red
    }
}
