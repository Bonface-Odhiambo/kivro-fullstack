================================================================================
KIVRO INBOX API - COMPANY INTEGRATION GUIDE
================================================================================

This guide explains how companies can integrate with the KIVRO Inbox API to 
send notifications to users. Companies like Hormuud, Dahabshiil, Somtel, etc. 
can use this API to deliver bills, alerts, and notifications directly to users' 
KIVRO inbox.

================================================================================
1. OVERVIEW
================================================================================

The KIVRO Inbox API allows verified companies to:
- Send individual notifications to users
- Send bulk notifications to multiple users
- Deliver bills, invoices, alerts, and promotional messages
- Track message delivery and read status

API Base URL: https://your-kivro-backend.com/api/inbox
Authentication: API Key (provided by KIVRO admin)

================================================================================
2. GETTING STARTED
================================================================================

Step 1: Company Registration
----------------------------
Contact KIVRO administration to register your company:
- Company Name
- Company Registration Number
- Contact Email
- Contact Phone
- Industry Type
- Logo URL (optional)

Step 2: Receive API Key
-----------------------
After approval, you will receive:
- Company Code (e.g., 'HORMUUD', 'DAHABSHIIL')
- API Key (e.g., 'hormuud_api_key_abc123...')
- Company ID (UUID)

⚠️ IMPORTANT: Keep your API key secure! Never share it publicly or commit it 
to version control.

Step 3: Test the API
--------------------
Use the provided test endpoints to verify your integration before going live.

================================================================================
3. API AUTHENTICATION
================================================================================

All API requests must include your API key in the request headers:

Header Name: x-api-key
Header Value: your-api-key-here

Example:
--------
x-api-key: hormuud_api_key_abc123def456ghi789

The API will automatically identify whether you're a government agency or 
company based on the API key.

4. API ENDPOINTS
================================================================================

4.1 SEND SINGLE MESSAGE
-----------------------
Endpoint: POST /api/inbox/send
Description: Send a notification to a single user

Request Headers:
{
  "Content-Type": "application/json",
  "x-api-key": "your-api-key-here"
}

Request Body:
{
  "user_id": "bbb9088c-074d-41cc-acac-320e55a34c2c",
  "category": "Telecommunications",
  "subject": "Your Monthly Bill is Ready",
  "message_body": "Dear Customer, your bill for January is now available...",
  "message_type": "invoice",
  "priority": "normal",
  "reference_number": "HRM-2025-001234",
  "metadata": {
    "bill_amount": 25.00,
    "currency": "USD",
    "due_date": "2025-02-15",
    "account_number": "252-61-XXXXXX"
  }
}

Response (Success):
{
  "success": true,
  "message": "Message sent successfully",
  "data": {
    "id": "message-uuid",
    "user_id": "user-uuid",
    "subject": "Your Monthly Bill is Ready",
    "sent_at": "2025-01-13T12:30:00Z",
    "sender_type": "company",
    "company_sender": {
      "company_name": "Hormuud Telecom",
      "company_code": "HORMUUD"
    }
  }
}

Response (Error):
{
  "success": false,
  "error": "User not found"
}

================================================================================
5. REQUEST PARAMETERS
================================================================================

Required Parameters:
-------------------
- user_id (UUID): The KIVRO user ID to send the message to
- category (String): Message category (see available categories below)
- subject (String): Message subject line (max 200 characters)
- message_body (String): Full message content (supports line breaks)

Optional Parameters:
-------------------
- message_type (String): Type of message
  Options: 'notification', 'invoice', 'alert', 'reminder', 'certificate'
  Default: 'notification'

- priority (String): Message priority level
  Options: 'low', 'normal', 'high', 'urgent'
  Default: 'normal'

- reference_number (String): Your internal reference/tracking number
  Example: 'HRM-2025-001234'

- metadata (JSON Object): Additional structured data
  Examples:
  - Bill: { "bill_amount": 25.00, "due_date": "2025-02-15" }
  - Alert: { "alert_type": "data_usage", "usage_percentage": 80 }
  - Delivery: { "tracking_number": "TRACK123", "estimated_delivery": "2025-01-15" }

7. MESSAGE TYPES & USE CASES
================================================================================

notification - General information, updates, announcements
invoice      - Bills, payment requests, statements
alert        - Urgent notifications, warnings, critical updates
reminder     - Payment reminders, deadline notifications
certificate  - Approvals, confirmations, official documents

================================================================================
8. PRIORITY LEVELS
================================================================================

low     - Promotional messages, general information
normal  - Regular bills, standard notifications
high    - Important alerts, payment due soon
urgent  - Critical alerts, immediate action required

Urgent messages are displayed prominently with red badges in the user's inbox.

async function sendNotification() {
  try {
    const response = await axios.post(
      'https://your-kivro-backend.com/api/inbox/send',

          bill_amount: 25.00,
          currency: 'USD',
          due_date: '2025-02-15'
        }
      },
      {
        headers: {
          'Content-Type': 'application/json',
          'x-api-key': 'your-api-key-here'
        }
      }
    );
    
    console.log('Message sent:', response.data);

    console.error('Error:', error.response?.data || error.message);
  }

sendNotification();

import requests
import json

def send_notification():
    url = 'https://your-kivro-backend.com/api/inbox/send'
    headers = {
        'Content-Type': 'application/json',
        'x-api-key': 'your-api-key-here'
    }
    data = {
        'user_id': 'bbb9088c-074d-41cc-acac-320e55a34c2c',
        'category': 'Telecommunications',

        'message_body': 'Dear Customer, your bill is now available...',

        'priority': 'normal',
        'reference_number': 'HRM-2025-001234',
        'metadata': {
            'bill_amount': 25.00,
            'currency': 'USD',
            'due_date': '2025-02-15'
        }
    }
    
    try:
        response = requests.post(url, headers=headers, json=data)
        response.raise_for_status()
        print('Message sent:', response.json())
    except requests.exceptions.RequestException as e:
        print('Error:', e)

send_notification()

    ]
];

    'http' => [
        'header' => [
            'Content-Type: application/json',
            'x-api-key: ' . $apiKey
        ],
        'method' => 'POST',
        'content' => json_encode($data)
    ]
];

$result = file_get_contents($url, false, $context);

    echo "Error sending message\n";
} else {
    echo "Message sent: " . $result . "\n";
}
?>

10. ERROR CODES & TROUBLESHOOTING
================================================================================

HTTP 401 - Unauthorized
-----------------------
Error: "API key is required" or "Invalid or inactive API key"
Solution: 
- Check that x-api-key header is included
- Verify your API key is correct
- Ensure your company account is active

HTTP 400 - Bad Request
----------------------
Error: "Valid user_id is required"
Solution: Ensure user_id is a valid UUID format

Error: "Category 'XYZ' not found"
Solution: Use one of the available categories listed in section 6

Error: "Subject is required"
Solution: Include a subject field in your request

HTTP 404 - Not Found
--------------------
Error: "User not found"
Solution: Verify the user_id exists in the KIVRO system

HTTP 500 - Internal Server Error
---------------------------------
Error: "Failed to send message"
Solution: Contact KIVRO support with the error details

11. BEST PRACTICES
================================================================================

1. Store API Keys Securely
   - Use environment variables
   - Never commit to version control
   - Rotate keys periodically

2. Validate User IDs
   - Verify user IDs before sending messages
   - Handle user not found errors gracefully

3. Use Appropriate Priority Levels
   - Don't overuse 'urgent' priority
   - Reserve 'urgent' for critical alerts only

4. Include Meaningful Metadata
   - Add structured data for bills, amounts, dates
   - Makes messages more actionable for users

5. Use Reference Numbers
   - Include your internal tracking numbers
   - Helps with support and debugging

6. Handle Rate Limits
   - Implement retry logic with exponential backoff
   - Use bulk endpoints for multiple users

7. Test Thoroughly
   - Test with sandbox/test users first
   - Verify message formatting and metadata

8. Monitor Delivery
   - Log successful and failed deliveries
   - Set up alerts for high failure rates
